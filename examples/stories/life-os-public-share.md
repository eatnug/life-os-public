# Life OS Public Share

This is a sanitized story/view derived from the example slices. It is not source memory.

The public share repo is meant to show the architecture without exposing the private life repo.

Current shape:

- `README.md` explains the high-level idea.
- `docs/architecture.md` describes slices, entities, stories, and runtime rails.
- `docs/roadmap.md` lists the open design problems.
- `examples/slices/` contains selected notes derived from actual Life OS system work.
- `examples/entities/registry.yaml` shows a small alias/identity layer.

Important correction:

The examples should not feel like fabricated demo data. They should be grounded in actual notes, then edited down for privacy and readability.

Open questions:

- How much editing can happen before a note stops being a real example?
- Should the public repo include source excerpts, generated views, or both?
- How can private context stay private while still making the system inspectable?
